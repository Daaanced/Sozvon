Существует определённый набор HTTP-методов, описанных в стандарте RFC 7231 и связанных спецификациях. Помимо самых популярных (GET, POST, PUT, DELETE), есть и другие, которые применяются в REST-архитектуре значительно реже, но знать их полезно.

## [Основные HTTP-методы]

1. GET

Получить данные.
Не изменяет состояние сервера.

📌 Пример:
GET /users — получить список пользователей.

2. POST

Создать ресурс или выполнить действие.
Тело запроса содержит данные.

📌 Пример:
POST /users — создать пользователя.

3. PUT

Полностью обновить ресурс.
Обычно требует полный объект целиком.

📌 Пример:
PUT /users/5 — заменить данные пользователя №5.

4. PATCH

Частично обновить ресурс.
Используется, когда нужно изменить только часть полей.

📌 Пример:
PATCH /users/5 — изменить только имя или только адрес.

5. DELETE

Удалить ресурс.

📌 Пример:
DELETE /users/5

## Дополнительные методы (встречаются реже)

6. HEAD

То же, что GET, но без тела ответа.
Используется для проверки доступности ресурса или метаданных.

📌 Пример:
HEAD /file.zip — узнать размер файла, не скачивая его.

7. OPTIONS

Вернуть список допустимых методов для URL.
Часто используется браузерами в CORS-запросах.

📌 Пример ответа:

Allow: GET, POST, OPTIONS

8. CONNECT

Открывает туннель к серверу.
В основном используется для HTTPS-прокси.

📌 Пример:
Браузер → прокси → делает CONNECT example.com:443.

9. TRACE

Возвращает клиенту полученный запрос.
Используется для отладки (почти всегда отключён из-за безопасности).
